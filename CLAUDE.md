## Repository layout

This git repo holds three things. Only the first two are actively developed:

- `app/` — Expo (React Native) client, SDK 58, React 19, Expo Router. Has its own `app/AGENTS.md` with Expo-specific rules; read it before touching Expo/EAS APIs.
- `WebAPISalo/` — ASP.NET Core 9 Web API (the backend the app talks to). Solution file: `WebAPISalo/WebAPISalo.slnx`; project: `WebAPISalo/WebAPISalo/WebAPISalo.csproj`.
- `AndroidApp/` — an unrelated Java/Gradle Android template (`com.example.myfristapp`). Ignore unless asked.
- `salo.itstep.click/` — production deployment files (`docker-compose.yml`, `.env`). `.env` holds real credentials; never copy its values into code, docs, or commits.
- `build_and_push.bat` — builds the API Docker image and pushes it to Docker Hub as `novakvova/salo-api:latest`.

Comments, UI strings and API error messages are in Ukrainian. Keep new user-facing text consistent with that.

## Commands

Client (run from `app/`; the project uses npm, `package-lock.json`, no bun):

```bash
npx expo install <pkg>     # add deps; always use this instead of npm install (picks SDK-compatible versions)
npx expo start             # dev server (also: npm run android / ios / web)
npx tsc --noEmit           # typecheck (strict mode)
npx expo-doctor            # dependency/config diagnostics
npx expo install --fix     # repair incompatible versions
```

- `npm run lint` maps to `expo lint`, but there is no ESLint config in `app/`, so it is not set up yet.
- There is no test runner configured in the client. Do not assume `jest` exists.
- Native folders (`ios/`, `android/`) are generated by CNG and gitignored; configure native behavior in `app.json` and config plugins.

Backend (run from repo root):

```bash
dotnet build WebAPISalo/WebAPISalo/WebAPISalo.csproj
dotnet run --project WebAPISalo/WebAPISalo          # Swagger UI is enabled in all environments
dotnet ef migrations add <Name> --project WebAPISalo/WebAPISalo   # EF Tools are referenced in the csproj
```

- There is no test project in the backend.
- Migrations are applied automatically at startup (`SeedIdentityAsync` in `Program.cs` calls `MigrateAsync`), so you do not need to run `database update`.

## Architecture (big picture)

### Client auth and navigation

- Routing is Expo Router, file-based under `app/src/app/`. Groups: `(auth)` (login, register), `(profile)` (profile). `index.tsx` redirects to `/profile` if a user is in Redux, otherwise to `/login`.
- Session state: Redux Toolkit store in `src/store/index.ts`, one slice `auth` in `src/store/reducers/AuthSlice.ts`. The slice stores the decoded JWT claims plus the raw `token`.
- Token persistence: `expo-secure-store` under the key `"token"`. The root `src/app/_layout.tsx` reads it on startup and dispatches `loginSuccess`. Login and logout write and clear the same key. The root layout's `useEffect` has no dependency array, so it re-runs on every render. Keep that in mind before adding logic there.
- The base URL is `API_BASE_URL` in `src/api/config.ts` (`https://salo.itstep.click`). All auth endpoints (login, register, forgot and reset password) are RTK Query mutations in `src/api/apiSlice.ts`. `profile.tsx` still hardcodes `https://salo.itstep.click/api/...`; move it to `API_BASE_URL` when you touch that screen. There is no env-based config.
- Auth requests: `src/api/baseQuery.ts` (`fetchBaseQuery`, adds `Authorization: Bearer` from `state.auth.user.token`). The `api` reducer and middleware are in `src/store/index.ts`. Use `getApiError` from `src/api/apiErrors.ts` to read the status and `error` text from RTK errors.
- Forms use react-hook-form with zod schemas in `src/schemas/`, wired through `@hookform/resolvers/zod`. Styling is NativeWind (Tailwind classes via `className`); the global stylesheet is `src/global.css`.
- `profile.tsx` posts to `/api/Account/Register` (not an update endpoint), because the backend has no profile-update endpoint.
- Chat: `app/src/app/mychat.tsx` (route `/mychat`) connects with `@microsoft/signalr` to `CHAT_HUB_URL` (`src/api/config.ts`), listens for the `Send` event and invokes `Send`. Messages are shown newest-first in an inverted `FlatList`. The route is not behind login. `profile.tsx` has a «Перейти в чат» button (`router.replace("/mychat")`); `mychat.tsx` has no way back.
- Password recovery: `(auth)/forgot-password.tsx` → `(auth)/reset-password.tsx` (email passed as a route param). Both use the RTK mutations from `src/api/apiSlice.ts`. `login.tsx` links to forgot-password and shows errors for statuses 400 and 401.

### Backend

- ASP.NET Core controllers with routes `api/[controller]/[action]`. Currently one real controller: `Controllers/AccountController.cs` (`Login`, `Register`, `GetAll`, `ForgotPassword`, `ResetPassword`). `WeatherForecastController` is template leftover.
- Identity: `AddIdentity<UserEntity, RoleEntity>` on EF Core with Npgsql (PostgreSQL). Keys are `long`. Password policy is minimal (length 6, no other rules).
- Auth: JWT bearer. `JwtTokenService` issues HS256 tokens valid for 7 days, with claims `email`, `name` (`"{LastName} {FirstName}"`), `image`, and one `roles` claim per role. The client decodes these claims directly, so renaming a claim breaks the app's user object.
- Roles come from `Constants/Roles.cs` (`Admin`, `User`). `SeedIdentityAsync` creates them and seed users `admin@gmail.com` / `user@gmail.com` when the Users table is empty. The seed code runs only once per empty database.
- Hub: `Hubs/ChatHub.cs` (`Send(string)` broadcasts to all clients), mapped at `/chat`. Messages are not stored and carry no sender.
- CORS: default policy in `Program.cs` allows any origin with credentials (`SetIsOriginAllowed(_ => true)` + `AllowCredentials`). `app.UseCors()` runs before `MapHub`.
- Images: `Services/ImageService.cs` compresses uploads with SkiaSharp and saves them under `ImagesDir` (default `images/`). That folder is served statically at `/images`. The path is resolved from the current working directory, so run the app from the project folder.
- Config: `appsettings.json` has the JWT key, empty `ConnectionStrings:DefaultConnection`, `ImagesDir`, `ImageSizes` and the `Smtp` section (`Host`, `Port`, `UserName`, `Password`). In Docker, the connection string comes from the env var `ConnectionStrings__DefaultConnection` (see `salo.itstep.click/docker-compose.yml`). Keep secrets in env vars (`Smtp__Password`, `Jwt__Key`), not in the file.
- Email: `Services/EmailService.cs` (MailKit) implements `IEmailService`, configured by `SmtpSettings` (`Models/Settings`, bound with `IOptions`). `SendPasswordResetCodeAsync` renders `EmailTemplates/PasswordResetCode.html` (copied to output by the csproj) and HTML-escapes `{{Email}}` and `{{Code}}`.
- Password reset: `ForgotPassword` and `ResetPassword` in `AccountController`. The 6-digit code is Identity's `DefaultEmailProvider` TOTP (purpose `ResetPassword`), not stored in the DB. `ResetPasswordAsync` updates the security stamp, which invalidates the code.

### Deployment

- The Dockerfile is multi-stage (SDK 9 build, ASP.NET 9 runtime) and listens on port 8080 inside the container.
- `docker-compose.yml` runs `novakvova/salo-api` on host port `8254`, plus `postgres:18.1` and a daily `pg_dump` backup container.
- nginx on the host proxies `salo.itstep.click` (and `*.salo.itstep.click`) to `localhost:8254`, with `client_max_body_size 200M`. Setup notes are in `README.md`.
- Release flow: run `build_and_push.bat` to push a new image, then pull and restart the compose stack on the server. Client builds go through EAS (`app/AGENTS.md`).

## Coding rules

Клієнт (`app/`):

- TypeScript strict. Без `any`; типи беруться з `src/types/`, а типи форм — через `z.infer` зі схем у `src/schemas/`.
- Імпорти в `src/` через alias `@/` (див. `tsconfig.json`), не відносні шляхи через кілька рівнів.
- Redux: лише типізовані хуки `useAppDispatch` / `useAppSelector` з `@/store`, не напряму з `react-redux`.
- Стилі для нового коду — NativeWind (`className`), не `StyleSheet`.
- Токен зберігати тільки в `expo-secure-store`. Не використовувати AsyncStorage чи localStorage.
- Не логувати паролі, токени та вміст форм. У наявних `console.log` у `login.tsx` і `profile.tsx` це порушено, тому не копіювати такі рядки.
- Не змінювати claim-и JWT (`email`, `name`, `roles`, `image`, `exp`) без синхронної зміни `IUser`.

Бекенд (`WebAPISalo/`):

- Nullable enabled. Усі I/O-методи — `async`, з `Async`-суфіксом і `CancellationToken`, якщо метод приймає запит.
- Нові DTO — у `Models/`, нові сервіси — за інтерфейсом у `Interfaces/` і реєстрація в `Program.cs`.
- Назви дій у контролерах — PascalCase (маршрут `api/[controller]/[action]` залежить від них).
- Помилки API — `{ error = "..." }` з текстом українською. Не використовувати ключ `erroor`.
- Не додавати нові обліковий запис чи дані в seed. Він запускається на продакшені при порожній БД.

Спільне:

- Коментарі й повідомлення для користувача — українською, як і в наявному коді.
- Не чіпати `AndroidApp/`, `salo.itstep.click/.env` і `build_and_push.bat` без явного запиту.

## Architecture rules

- Клієнт: екрани тільки в `src/app/`. Некомпонентний код (API, утиліти) — поза `src/app/`. Компоненти в `src/components/` не звертаються напряму до мережі.
- Клієнт: стан сесії — тільки в Redux (`auth`). Не дублювати `user` або `token` у `useState` екрана.
- Клієнт: нові HTTP-виклики має йти через один модуль з базовим URL (наприклад `src/api/`), а не через захардкоджений рядок у екрані. Логін, реєстрація і відновлення пароля вже йдуть через RTK Query (`src/api/apiSlice.ts`). `profile.tsx` ще робить прямий виклик; переписати його під час зміни, а не окремою задачею.
- Бекенд: шар `Controllers → Interfaces → Services → Data`. Логіку пишемо в сервісі, контролер тримаємо тонким. Поточний `AccountController` напряму використовує `UserManager`; для нових дій так само прийнятно, але бізнес-логіку в контролер не додавати.
- Бекенд: зміна моделі Identity або `MyDbContext` — тільки разом з `dotnet ef migrations add`. Застосовані міграції не редагувати.
- Зображення: завжди через `IImageService`. Не писати файли напряму з контролерів.
- Продакшен-конфіг (`ASPNETCORE_ENVIRONMENT=Production`) не має залежати від Swagger чи seed-логіки, яка зараз увімкнена безумовно. Якщо міняєш `Program.cs` у цих місцях, роби умову явною.

## Testing rules

Стан: тестової інфраструктури немає ні в клієнті, ні в бекенді. Не припускати, що `jest`, `xunit` чи їхні конфіги вже є.

Перевірка перед завершенням задачі (що є зараз):

- Клієнт: `npx tsc --noEmit` з `app/`. Лінт не налаштовано, тому його не вважати перевіркою.
- Бекенд: `dotnet build WebAPISalo/WebAPISalo/WebAPISalo.csproj`.
- Зміни UI перевіряти запуском `npx expo start`, а не лише типами.

Коли додаємо тести (потрібне підтвердження користувача перед установкою пакетів):

- Клієнт: `jest-expo` + `@testing-library/react-native`, установка через `npx expo install`. Тести — поруч із кодом, як `*.test.ts(x)`.
- Бекенд: окремий проєкт `WebAPISalo.Tests` (xUnit + `Microsoft.AspNetCore.Mvc.Testing`), доданий у `WebAPISalo.slnx`.
- Пріоритет покриття: `AuthSlice` (reducers), zod-схеми, `JwtTokenService` (claims і строк дії), `AccountController.Login/Register`.
- Тести ніколи не ходять у `https://salo.itstep.click` і не підключаються до продакшен-БД. Для бекенда — окрема тестова БД або in-memory-варіант.
- Виправлення багу має супроводжуватись тестом, що відтворює баг, коли інфраструктура вже є.

## Gotchas

- `AuthSlice.ts` starts with `token = undefined`, so the initial state is always logged out. Session restore happens only in the root layout.
- `Register` in `AccountController` has a typo in its error key (`erroor`). Clients reading that field will see nothing.
- Use `npx expo install` for packages. Adding deps with raw npm can pull versions that don't match SDK 58.
- After adding a route file under `src/app/`, run `npx expo start` briefly to regenerate `.expo/types`. Until then `typedRoutes` doesn't know the route, and `npx tsc --noEmit` fails on `router.push`.
- `ForgotPassword` always returns 200, even for an unknown email. Don't use its status to check whether a user exists.
- `Login` returns 401 for wrong credentials, not 400. The client handles both.
- `Register` returns the error under the key `erroor`, so `getApiError` finds no message and the UI shows the fallback text.
